CLOSED NETWORK — MANAGE USERS, CURRICULUM, PROGRESS
====================================================

Needs: python3 + git (for progress branches). No pip. No internet day-to-day.

Start the lab
-------------
  ./run.sh                         student dojo
  ACADEMY_ADMIN=1 ./run.sh         dojo + admin at /admin

Or:  python3 -m academy.cli admin


1) Users / login
----------------
Admin UI → Users, or CLI:

  academy users add alice --name Alice
  academy users add bob --name Bob --role student
  academy users list
  academy users disable bob

On the dojo, students **Log in** with their username (accounts are created
by the instructor — unknown usernames are rejected).


2) Curriculum — add / remove challenges
---------------------------------------
Admin UI → "+ New challenge" (wizard) or "Remove challenges".

CLI create goes through the admin UI / API. Deleting:

  # from admin UI "Remove challenges"
  # or API: POST /api/admin/challenges/delete  {"id":"my-challenge"}

Curriculum files live under curriculum/. Keep that folder in git on the
instructor machine so you can version and ship updated packs.


3) Progress — auto branches on first run
----------------------------------------
On the **first run** of the application a bare git repository is created:

  .academy-data/academy-progress.git

Each operator gets their own branch that **auto-updates** on every solve / login:

  progress/<user_id>     contains only progress.json

Live files + working mirror:

  .academy-data/progress/<user>/progress.json
  .academy-data/progress-git/.git

No manual push is required on a single lab. Inspect with:

  academy progress status
  # shows remote → academy-progress.git and progress/<user> branches

Optional: point the same mirror at GitHub (or an on-prem remote) when the
network allows — progress will auto-push there instead:

  academy progress remote https://github.com/ORG/academy-progress.git
  # or Admin → Progress sync → Save remote

  academy progress push     # bulk push all users
  academy progress pull     # import branches onto another lab

Admin UI → Progress sync shows the auto-created remote and branch list.


Typical closed-network workflow
-------------------------------
1. Instructor laptop: maintain curriculum, build portable pack.
2. USB the .tar.gz into the lab. Extract. ACADEMY_ADMIN=1 ./run.sh
   → first run creates academy-progress.git automatically.
3. Create users. Students Log in and play. Each clear updates
   progress/<username> on the local progress repo.
4. Optional (USB or brief network window): retarget remote to GitHub and push.
5. Review student branches: progress/alice, progress/bob, …


Ship an updated pack
--------------------
  bash scripts/pack_portable.sh
  # copy dist/pi-sdr-academy.tar.gz (or portable/pi-sdr-academy.tar.gz)
